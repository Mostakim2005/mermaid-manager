Mermaid Manager (MermaidApp Studio)

Offline draw.io + two-way visual Mermaid suite for Windows — plain-English map of intentions, architecture, decisions, and landmines.

[FEATURE: Two-Way Visual Mermaid Editor]Active Feature
Drag nodes, edges and subgroups visually; the Mermaid source syncs both ways with the draw.io canvas.

User Intention: Every button responds instantly, a starter flowchart greets you, and a built-in help panel teaches the workflow.

[FEATURE: Universal Code-to-Diagram Studio]Active Feature
Paste any diagram code — 22+ syntaxes auto-detected, rendered live, broken Mermaid repaired with an explained one-click fix.

User Intention: Auto-Fix must say what it repaired in plain English and never rewrite working code blindly (sequence/class diagrams pass through untouched).

Code Anchor: plugins/mermaid-visual-editor.js → openUniversalStudio · renderCurrentCode · autoFixSyntaxDetailed
[FEATURE: Diagrams and Folders Workspace Hub]Active Feature
Folder tree with live-preview cards, favorites, a default save folder, plus real PC folders holding your .mmd/.md diagrams.

User Intention: All confirmations through in-app dialogs; PC folders stay authorized across launches; removing a folder never deletes your files.

Code Anchor: plugins/mermaid-visual-editor.js → openDiagramsHub · addDiskFolder · getDefaultFolderId · inAppDialog
[FEATURE: Electron Disk Access over IPC]Active Feature
Four security-screened IPC actions give the hub real read/write power only inside folders you authorized through the native picker.

User Intention: Grants persist across launches; traversal, reserved device names, wrong extensions and oversized content are refused.

Code Anchor: src/main/electron.js → mermaidAuthFolder · mermaidContainedChild · reqMermaidName
[FEATURE: Portable EXE, Installer and Auto-Versioned Releases]Active Feature
Every release carries two downloads — a no-install portable .exe and a per-user Windows installer — built in the cloud with an automatically bumped version tag.

User Intention: No manual versioning and no local build: an app-code push to master releases both files; the installer needs no admin rights and creates shortcuts.

Code Anchor: .github/workflows/build.yml → Work out the release version · electron-builder-win.json → win.target (portable + nsis)

[DECISION: In-App Dialogs Replace Native Prompt]DECIDED BY: AGENT - Approved by Human
Electron deletes window.prompt(); the hub now uses themed DOM dialogs for every question and confirmation.

Why We Pivoted: Native prompt threw "prompt() is not supported" mid-handler, aborting folder creation; confirm() could not collect text. In-app dialogs also stop key events leaking into canvas shortcuts.

Code Anchor: plugins/mermaid-visual-editor.js → inAppDialog · appPrompt · appConfirm
[DECISION: Blessed-Path IPC for Disk Access]DECIDED BY: AGENT - Approved by Human
Real PC folders work through four main-process actions reusing draw.io's security model — not a blanket fs grant.

Why We Pivoted: webkitdirectory kept no paths and could not write; a generic grant would let a renderer XSS read anything. Blessed folders + sanitized child paths + realpath containment keeps the boundary.

Code Anchor: src/main/electron.js → mermaidAuthFolder · mermaidContainedChild · reqMermaidName

[DECISION: One Flattened Repository for Cloud Builds]DECIDED BY: AGENT
Three nested repos became one repo, so a GitHub Actions runner can check out the whole app and build the portable exe on a version tag.

Why We Pivoted: the old root repo held only gitlinks with no .gitmodules, so a cloud runner would get two empty folders. Real submodules would mean three public repos and three pushes; flattening needs one checkout. Nested history is kept in a local backup.

Code Anchor: .gitignore · .gitattributes · .github/workflows/build.yml → build-portable
[DECISION: Release Tag Is the Version Source of Truth]DECIDED BY: AGENT
The version is computed from the newest tag (next patch), stamped into the app, and published with its own tag — no manual version bookkeeping.

Why We Pivoted: sync.cjs overwrote package.json from drawio/VERSION, so a pushed tag could never change the built version. Now an app-code push to master auto-releases both the portable build and the installer; docs-only pushes are filtered out.

Code Anchor: .github/workflows/build.yml → Work out the release version · electron-builder-win.json → nsis
[TRAP: Config JSON BOM Breaks Blessed Paths]DO NOT TOUCH
Never write %APPDATA%\draw.io\config.json with a PowerShell-5.1 UTF-8 BOM — the store fails to parse and every folder access reports "path not authorised".

What Breaks If You Touch It: electron-store silently loads nothing; blessedPaths is empty; the security layer correctly refuses all folders. Write BOM-less with UTF8Encoding($false).

Protected Anchor: src/main/electron.js → BLESSED_PATHS_KEY store init
[TRAP: Visual Editor Hydration Needs Absolute /_next/ URLs]DO NOT TOUCH
Never hand-copy the editor build or rewrite /_next/ to relative paths — Turbopack never boots and every button goes dead.

What Breaks If You Touch It: React never mounts; the UI renders as a static shell ignoring all clicks. Always deploy via scripts/sync-visual-editor.cjs.

Protected Anchor: scripts/sync-visual-editor.cjs · src/main/electron.js → /_next/ redirect
[TRAP: Electron Removes Prompt and Confirm]DO NOT TOUCH
Never add new prompt()/confirm() calls in the renderer — the throw aborts the whole click handler silently.

What Breaks If You Touch It: Storage never updates and the UI appears simply broken behind an opaque error dialog. Use appPrompt/appConfirm.

Protected Anchor: plugins/mermaid-visual-editor.js → inAppDialog
[TRAP: Plugin Idempotency Guard Is Window-Global]DO NOT TOUCH
Never move __mermaidStudioPluginInitialized into a closure — draw.io loads the plugin from multiple bootstraps and palettes would duplicate.

What Breaks If You Touch It: Sidebar palettes and toolbar buttons register two or three times.

Protected Anchor: plugins/mermaid-visual-editor.js → initMermaidStudioPlugin · injectNativeToolbarButtons
[TRAP: CSP / base-uri Interactions With the Iframe]DO NOT TOUCH
Never loosen the CSP or inject base elements to "fix" asset loading — the sanctioned path is the electron.js /_next/ redirect.

What Breaks If You Touch It: The strictest policy wins; weakening it exposes the whole editor, and base-tag experiments silently re-route every relative URL.

Protected Anchor: src/main/electron.js → onHeadersReceived · onBeforeRequest
[TRAP: ELECTRON_RUN_AS_NODE Leaks Into Verification Spawns]DO NOT TOUCH
Node-launched Electron must always strip ELECTRON_RUN_AS_NODE or it starts as a plain REPL — no app, no CDP, probes hang.

What Breaks If You Touch It: "app page target never appeared" errors that look like app bugs are actually environment leaks.

Protected Anchor: scripts/verify-ipc-integration.mjs → childEnv · scripts/verify-packaged-exe.mjs
